TASK-0188 · One chat stream · round 2

Round 1 picked C, "Say or Do". Since then the operator replaced the hold window with a quiet window: 2 s after the last message an 8-segment ring appears and empties over 8 s. When it empties, the DM reads the conversation and asks for a 👍 on its reading of each action. The axis now: does the player still mark a deed?

A — Just talk

One Send button

Thesis. Players talk like at a real table, and the DM always checks its reading before anything rolls.

Risk. Every deed waits at least 10 s plus a model call. A deed the DM misses never gets a confirm, so the player has to say it again more plainly.

B — Talk, or flag a deed

Send with a Do flag

Thesis. The DM still words and checks every action, but the player can say "this one is a deed, don't miss it".

Risk. It brings back a choice. The deed flag is a new field on talk: a frozen-contract amendment to TalkV1.

Shared baseline

Static ring (5 of 8) and the animated pacing demo.
  • Quiet window. The server sets the D19 talk turn's notBefore to the last post + 10 s. Clients draw the ring from the last post's arrival. Any public IC post or @dm post restarts it. OOC chatter does not.
  • Thinking. When the turn is claimed, the ring becomes a pulsing "The DM is reading the table…" chip.
  • One DM read. It returns one outcome: none, reply, scene, escalate, or the new confirm.
  • Confirm row. A public DM row, set apart from narration, with one line per proposed action. 👍 Yes commits. Not quite opens the composer. An unanswered confirm commits nothing.
  • Interrupt. During Thinking, Send reads "Send — interrupts the DM". An inline strip asks I'm sure or Wait. OOC posts skip it.
  • Turn mode. The active player's ring is 1 s + 4 s.
  • No modals. Chat is a view over the event log. A VTT can drive the same events.

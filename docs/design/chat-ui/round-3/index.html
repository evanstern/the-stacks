Chat UI — Design Round 3

TASK-0028. A narrow round: the base shell, tokens and palette are settled (round 2’s A2 daylight, teal in both light and dark — Nightshift is rejected). This round decides one thing — how the operator picks which books a chat session answers from — under three operator rulings: no modals anywhere, “add a book” from Ask means adding to the session’s available knowledge base, and a book without embeddings stays keyword-searchable with an always-available, never-forced “Embed now.”

  • P — Slide-out panel

    A “Sources” button in the Ask header opens a panel anchored to the right edge (a bottom sheet on mobile). Full book list, checkboxes, status, add-a-book, all in one place.

  • D — Autocomplete dropdown

    Selected books show as chips above the prompt bar; “+ Add source” or typing “@” opens an anchored, filterable dropdown of every book.

Operator rulings this round applies

  • No modals, ever. Neither option uses a native popup-window element or a centred backdrop overlay. P slides a panel in from the right edge (a bottom sheet on mobile); D anchors a dropdown to the chip row. The Library delete confirmation (state 7 in both files) is redone as an inline row that expands beneath the book, replacing round 2’s popup-window element.
  • “Add a book” from Ask adds a source to the session’s knowledge base. Both options let you upload without leaving Ask: P runs the upload inline inside the panel (progress card pinned to the top of the list); D expands an inline upload row under the chip row.
  • Books without embeddings stay keyword-searchable, never re-imported. Equipment is shown “Search-only” and selectable in both options, with an “Embed now” affordance available at any time (state 5), never forced.

Chat UI — Design Round 2

TASK-0028. Operator picked direction A from round 1. This round develops it into one full layout — sidebar, a three-pane Ask, a proper Library page, and the shared Table — shown in two accent/colour palettes so the operator can pick a mood without re-judging the layout.

  • A2 — Daylight

    Light-first: white and cool-grey surfaces, one deep-teal accent (#0f6f63), matching dark mode.

  • A2 — Nightshift

    Dark-first: charcoal surfaces, one saturated violet accent (#a48cf0), matching light mode — the reference-4 mood the operator liked.

What changed from round 1

  • Colour. Round 1’s sepia/reference-desk palette is gone. Both files now carry a single confident accent on neutral grey/white or charcoal surfaces, chosen from the operator’s reference boards (light dashboard, dark AI console).
  • Library is a real page, not a disclosure. Round 1 put upload and the book list in a collapsible panel above the chat. That panel is gone; Library is now its own sidebar destination with the reference-2/3 treatment (dropzone, uploading-file card, recent imports, books table). The Ask page keeps only a compact strip of ready books plus an “Add a book” link, so uploading never leaves chat context if you don’t want it to.
  • A left sidebar replaces the old top-level nav. Ask, Library and Table are peers in one sidebar, with Settings and the signed-in user pinned at the bottom — the reference-1 and reference-4 pattern the operator called out. It collapses to icons (state 18).
  • A session list is now visible. Reference 4’s grouped chat-session list ("Today" / "Yesterday") is added as the Ask page’s left column, badged SES as a proposed follow-up card (TASK-0039) rather than part of this task’s scope.
  • Mobile is designed, not just squeezed. The sidebar becomes a bottom tab bar; Ask gets a Chat/Source segmented control that jumps to Source automatically on citation click, with a “Back to answer” control (state 15); Library keeps the same dropzone/upload-card pattern at 390px (state 16).
  • Table is drawn, not just named. State 17 shows the M0 shared-play answer to the two-browsers acceptance criterion directly: an operator browser (Ask + Library + Table in its sidebar) and a player browser (Table only) side by side, both rendering the same event log — library content only ever appears on the operator’s side.
  • Citation mechanism is unchanged. Direction A’s pinned source pane that loads a clicked citation’s passage in place is kept verbatim, now living in the third Ask column instead of a two-pane split.

Open questions for the operator

  • Session titles: auto-derived from the first question (as shown), or does the operator get to rename/pin a session?
  • “Add a book” from the Ask strip — does it navigate to the Library page (losing chat scroll position), or open Library as an overlay/panel so the conversation stays mounted?
  • Does the sidebar’s collapsed-to-icons state (18) persist per operator, or reset every session?
  • On the Table page, should the operator’s Ask/Library sidebar items stay visible while a session is live, or does “going to the table” hide them to keep the operator’s attention on shared play?
  • Equipment’s “Search-only” status (4b) — is that a permanent book state, or does it flip to a normal ready state once an AI provider is configured, requiring a re-embed?
  • Palette pick: daylight’s teal or nightshift’s violet as the one shipped default (both still support the opposite mode via the toggle)?

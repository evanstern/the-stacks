TASK-0236 · MUD-derived UX · round 1

Keep the MUD architecture (one text stream plus server-pushed state beside it), drop the MUD command grammar, and make the map a peer panel whose every fact also lands in the stream as text. The four options differ on one axis. Everything else is held constant: composer, rows, copy, states.

The axis: how much screen the text stream owns

A 100%B ~80%C ~50%D ~20%

A — Scroll

Thesis. The stream is the whole table. State lives in a one-line status strip and inline expansions, like a MUD prompt.

Risk. Once a map exists it has nowhere to live, and spatial play degrades into prose.

B — Margin

Thesis. The stream owns most of the width. A slim right margin holds party, turn order and conditions, like Nexus gauges beside the output. The map opens as a slide-out panel.

Risk. At 390px the margin collapses, so it needs a persistent mini-strip anyway.

C — Split

Thesis. Map and stream share the screen, docked side by side like Mudlet's mapper. Clicking a token or exit drafts a line in the composer.

Risk. At 390px one half must collapse, and the map competes with the conversation.

D — Board

Thesis. The map and panels own the screen. The stream shrinks to a collapsible log, like Foundry. Most actions are clicks.

Risk. It abandons natural-language-first play and screen-reader parity. It is the bound for "too far".

Shared baseline

  • One input line. Up/Down recalls history. @ or / opens a dropdown: @dm, /roll, /ooc, /help here.
  • Tab completes entity names (Sn → Snag).
  • Entity names in narration are links. A click expands player-safe facts inline.
  • Filter chips: All · In character · Table talk · Rules.
  • Roll rows collapse to one line and expand inline.
  • Status strip with HP, AC, conditions and turn, always as text.
  • Room block with ways on, each one clickable.
  • No modals. Slide-out panel (right on desktop, bottom sheet at 390px).

Each page has a state switcher (1 to 8) and accepts #state=N.

# the-stacks — grounding wiki

Code-grounded notes for this repository, one per concept, each pinned to the commit it was
verified against. Load this index first and route; load notes just-in-time rather than
bulk-loading the corpus. `CAPSULES.md` carries the same one-liners for whole-corpus
orientation.

**State of the codebase at this pin:** M0, the walking skeleton, plus the first `library` DB scene and playtest integration tests carry load-sized timeouts (TASK-0154, specs/056) and pass three consecutive full runs. TASK-0209 (specs/073) makes a human's clarify hold the turn and voices the clarify question in the fallback. TASK-0113 (specs/074-player-agency) adds one shared agency rule to every DM prompt, reflex facts derived from the ledger, and two deterministic agency checks ([[dm-narration-quality]], [[dm-runtime]]). TASK-0205 (specs/077) asks before an undeclared manner check or another human's roll, a clarify that holds the turn ([[dm-failure-and-gates]], [[dm-runtime]]). Spec 078 (specs/078-revealed-npc-present) lets the Director name offstage seed NPCs now on screen; resolve logs them as `arrived` rows ([[dm-runtime]], [[seed-npc-presence]]). TASK-0208 (specs/079-engine-opportunity-attack) gives the engine a per-round reaction flag, plans a `move` step, runs the hostile's opportunity attack in resolve, refuses a foreign actor with `STEP_ACTOR_MISMATCH`, and carries open followUps into later beats ([[dnd5e-engine]], [[dm-runtime]], [[dm-failure-and-gates]], [[dm-narration-quality]]). TASK-0127 (specs/070-stakes-before-dice) makes a check declare a consequence per outcome band before the dice, bands the engine result (success, success at a cost, failure, severe failure; natural 20 and 1 by table rule), resolves effects by band, makes a retry with no new risk free, and has narrate, audit and the ledger deliver the band ([[dnd5e-engine]], [[dm-runtime]], [[dm-failure-and-gates]], [[dm-narration-quality]]).
plane work. Every M0 seam exists and is demonstrated end to end — monorepo, compose stack,
Postgres event log, session auth, a WebSocket gateway, and a React Router 8 SSR app
(doc-0003 / decision-0008, superseding the earlier SPA). The `library` plane

([[ingestion]], TASK-0024: streamed upload → zip/HTML/Markdown → parse → chunk → store →

vector/fts/hybrid search, fused by RRF) now has its first HTTP caller: the rules answerer
([[rules-answerer]], TASK-0027, `POST /library/ask`) streams a cited, verified answer over SSE,
operator-only. The provider-agnostic AI gateway ([[ai-gateway]]) has landed, with two callers
now — ingestion's `embed()` and the rules answerer's `chat()`/`embed()`. Both now have a UI
([[chat-ui]], TASK-0028): upload-and-watch-it-ingest, ask-and-watch-it-stream with clickable
citations, and a much smaller Table-only view for a player, role-gated at the loader. The play route ([[play-route]], TASK-0047) now renders the table at `play/:sessionId` (and operator-only `play/fixtures`): transcript, composer, action cards, ledger and DM approvals slide-outs, all writing through the proposal gate. The pure 5e rules engine ([[dnd5e-engine]], TASK-0042) is a standalone package, called by the DM runtime. The SRD 5.2.1 data package ([[srd-data]], TASK-0043) adds 1020 validated records (903 at TASK-0043, plus 117 rules records from TASK-0123) with provenance, an id/name loader, a 120-token compact lookup form and the CC-BY attribution shown on `/about`. The session model ([[session-model]], TASK-0044) adds the typed event catalog, `canSee` visibility, the pure projection fold and fixtures, with an atomic `appendBatch` in the event log. The proposal gate ([[proposal-gate]], TASK-0045) now stands between producers and the log: typed proposals routed by `auto`/`ask`/`suggest` policy and DM seat, commit authority by table mode, refuse-before-write, atomic approval, an `expectedLastSeq` guard in the log, per-viewer WebSocket delivery (`canSee`), and an import-graph write-boundary test; the legacy uncatalogued `send` path is retired (TASK-0099, specs/043): an uncatalogued type is now refused with `UNKNOWN_EVENT_TYPE`. The AI DM runtime ([[dm-runtime]], [[dm-turn-jobs]], TASK-0046) now plays a scene: `turn`/`companion`/`chronicle` jobs on the shared `jobs` table (migration 0004; ingest rows stay `kind = 'ingest'`), a fixed assemble-director-interpret-adjudicate-resolve-narrate-audit pipeline, resolve as the only writer through the gate with the engine owning every number, digit-free narration audited up to three times with a factual fallback, seven `dm.*` gateway purposes (a failed turn records its failure and bounded model-output excerpts in `jobs.result`; skills, conditions and damage types are closed lists derived from engine enums, while spells and modifier/DC derivation are not gated yet), AI companions, operator `/dm` routes and a hand-authored scene seed. A usage ledger and operator debug routes ([[debug-view]], TASK-0116, migration 0005) now record every DM model call (provider, model, tokens, cost) and serve events, jobs, seed and calls read-only. The operator debug page ([[debug-view]], TASK-0117, `play/:sessionId/debug`, reached from a Debug link in the play header) polls those routes and shows why the table is waiting, a job timeline linked to the event log, a scrubbable state column, and seed, ledger, journal and cost slide-outs, with a Retry for a failed or stuck turn. Narration quality ([[dm-narration-quality]], TASK-0106) now keeps DM-only seed text out of player-facing prompts through a `PlayerSeedView`, names speakers in public-only transcripts, extends the narration facts, derives audit pass/fail in code with blocking and advisory issues, and ships an in-fiction deterministic fallback. The playtest harness ([[playtest-harness]], TASK-0048) plays a scripted seat through a scene in process, audits it (six code checks plus a `playtest.audit` call per segment), and ships `pnpm playtest run|audit|estimate` with a provider-mode spend ceiling. Companion reactions (TASK-0114, specs/036-companion-react) close the stall where a human objected to a companion's action and nothing answered: a human comment on a companion's open action queues a coalesced `react` run ([[dm-turn-jobs]]) in which the companion commits, withdraws (new `action.withdraw` / `action.withdrawn`) or revises ([[dm-runtime]], [[proposal-gate]]), and the play route shows a Withdraw control ([[play-route]]). The actor snapshot ([[actor-snapshot]], TASK-0140, decision-0025 U1) replaces every per-prompt state renderer: one typed snapshot of party, monsters and seed NPCs is built at assemble (S0) and after resolve (S1, with a diff), rendered in a `dm`, `seat` or `fiction` view under a token cap, and fails the turn loudly with `state-overflow` rather than show a model a partial state. Presence ([[presence]], TASK-0051, decision-0024) now tells every client who is at the table through an opt-in `presence` frame and a strip in the table header, and logs a `presence.recorded` marker once per DM turn that the Director's assemble node reads. The M2 demo ([[m2-demo]], TASK-0048) is its first use: a human-played scene and a scripted provider run, both audited, every finding resolved and the record signed by the operator. Group sign-off (TASK-0049, specs/044-group-signoff) makes a party action with two or more human players commit only when every present player has approved: a pure `signoffState` rule in [[session-model]], planner auto-commit and a `signoff` presence marker in [[proposal-gate]], and per-player sign-off rows with Approve and Object in [[play-route]] ([[presence]]). Encounter end resolves ([[dm-runtime]], [[dm-turn-jobs]], TASK-0110, specs/045-encounter-end-resolves) reorders resolve into six groups so an action that ends the encounter resolves before the Director's closing moves. Able-actor gates (TASK-0112, specs/046-downed-hero-gate) stop a downed hero from acting: the engine refuses `ACTOR_UNABLE` ([[dnd5e-engine]]), the declare gate refuses `CHARACTER_UNABLE` ([[proposal-gate]]), a plan gate refuses unknown combatants ([[dm-failure-and-gates]]), resolve settles downed turns with death saves ([[dm-turn-jobs]]) and the playtest seat stops declaring ([[playtest-harness]]). Suggest-policy proposals (TASK-0100, specs/047-suggest-no-approve) show a Suggestion label and Dismiss, never Approve, on the DM approvals list ([[play-route]]); the gate is unchanged. Scene presence (TASK-0141, specs/048-scene-presence) logs whether an actor is `present`, `yielded` or `absent` as a `scene-presence.changed` event ([[session-model]]) proposed under policy `ask` ([[proposal-gate]]), read into every snapshot ([[actor-snapshot]]), produced by a resolve `presence` effect that skips the second turn advance when the active actor leaves ([[dm-runtime]], [[dm-turn-jobs]]), enforced by the plan and declare gates with `absent` ([[dm-failure-and-gates]]), and backed by the engine `initiative.leave` ([[dnd5e-engine]]). Turn-mode floor passing (TASK-0050, specs/049-turn-floor) adds a `floor` proposal (end, take, return) with shared turn rules in [[session-model]] and [[proposal-gate]], an AI DM stall override, a `floor` job that passes an absent human's turn after 30 s and commits a stalled party action after 120 s ([[dm-turn-jobs]], [[presence]], migration 0007 in [[database-schema]]), and header floor controls, a turn-order strip and floor lines in [[play-route]]. The gate orders each session's writes in process and retries outside conflicts with a jittered wait (TASK-0157, specs/052). Script mode (TASK-0158, specs/053) lets a worktree stack replay a shipped DM script with no provider key: `DM_FAKE_SCRIPT=<name>` replaces the whole AI config and boot refuses it off worktree stacks ([[ai-gateway]], [[configuration]], [[runtime-stacks]]). Output claim gate (TASK-0143, specs/051-output-claim-gate) checks narration, rulings and roll reasons against the snapshot and the diff, so a dead, downed or absent actor never acts or speaks and deaths, drops and counts land on the right actor ([[output-claim-gate]], [[dm-runtime]], [[actor-snapshot]]). Model-call headroom (TASK-0192, specs/067) raises every `dm.*` `maxTokens` default to 4000 and records a capped call as outcome `truncated` (migration 0008; [[ai-gateway]], [[dm-runtime]], [[debug-view]], [[database-schema]]). Seed NPC presence (TASK-0142, specs/050-seed-npc-presence) makes the scene seed declare each NPC's presence per beat and turns it into logged `scene-presence` rows (`dm` rows at scene start, `arrived` rows at encounter start) that every NPC list reads ([[seed-npc-presence]], [[actor-snapshot]], [[dm-runtime]]). No
codex, system modules, or agents yet. `main` is now continuously deployed to a real hosted
`dev` environment on vm-104 ([[hosted-dev]]). Two humans can now share one table (TASK-0163, specs/054): the operator invites a player from Settings, the player redeems on the sign-in card, and the operator starts the `greyhollow-ford-duo` scene from a Start scene slide-out ([[scene-panels]], [[seed-npc-presence]], [[hosted-dev]]). The `greyhollow-ford-trio` seed seats three humans and no AI companion, so the operator starts a three-player table from the same slide-out (TASK-0176, specs/061; [[seed-npc-presence]], [[hosted-dev]]). A human DM changes scene from a Change scene slide-out seeded by the AI DM's scene suggestions, and carrying one out closes the suggestion so the AI DM's next turn queues (TASK-0159, specs/055; [[scene-panels]]). Roll resume (TASK-0168, specs/057-human-dm-roll-resume) stops a human DM's approved roll from being re-proposed: an action awaiting a ruling leaves every turn's beat, and the turn after approval reuses the paused plan instead of interpreting again ([[dm-runtime]], [[dm-turn-jobs]], [[runtime-stacks]]). The plan gate (TASK-0161, specs/058-roll-reason-plan-gate) now checks each step reason, `autoFail.reason` and condition `source` against the S0 snapshot with `checkClaims` and refuses a contradicting group with `REASON_CONTRADICTS_STATE` before any step runs ([[dm-failure-and-gates]], [[output-claim-gate]]). The operator header offers Start scene only when the server says no start is in flight (TASK-0167, specs/059): `GET /dm/sessions/:id/start` returns `none`, `queued`, `pending` or `started`, the button hides otherwise, and the header shows "Scene start queued." or "Scene start waiting for the DM." ([[scene-panels]], [[play-route]], [[dm-runtime]]). The human DM ends an encounter or switches between free and turn mode from a Table mode slide-out (TASK-0165, specs/060): an `encounter.end` `mechanics` request and `table-mode` requests, with no server change ([[play-route]], [[turn-floor]], [[scene-panels]]). The operator seats a human DM, or returns the seat to the AI DM, from a DM seat slide-out (TASK-0177, specs/062): a `dm.seat` request through the unchanged gate, a resync from seq 0 when the seat arrives, and a Start scene refusal for the DM on a character seat, with no server change ([[play-route]], [[scene-panels]], [[client-session-hook]], [[hosted-dev]]). In free mode a plan now resolves only its first stage: a code-only cut after adjudicate keeps the first run of like checks, records the rest as `followUps` the narrator says were not yet attempted, and holds the Director's turn, tracker and scene-end moves for that beat (TASK-0182, specs/064). A public in-character `talk` post under an AI seat now queues a coalesced `talk` turn: code triggers and at most one `react` call ship one reply, a scene beat or an escalation into an unstarted encounter, and a chain cap of two DM reactions stops the loop (TASK-0180, specs/065; [[dm-talk-triggers]]). A plan step may now name a non-combatant NPC (a check target, a condition or heal effect), and resolve pulls that NPC into the scene before the step runs (TASK-0194, specs/068; [[dm-failure-and-gates]], [[dm-runtime]]). Since spec 075 (TASK-0210) an attack or damage step may name such an NPC too, after the operator's ruling that attacks should reach anyone.

## Rules engine

- [[dnd5e-engine]] — the pure 5e engine package: `execute(state, command, rng)` to events or a refusal, seeded/scripted RNG, roll ledger, refuse-before-draw, no-I/O boundary, and the R8 arithmetic ruling.

- [[dm-runtime]] — the AI DM: node pipeline, resolve as the only gate writer, digit-free audited narration, `dm.*` purposes, scene seed and doctrine (MIT NOTICE), companions, chronicle, the Director's `arrivals` field (spec 078), `/dm` routes (including `GET /dm/seeds`), the `dm/` import boundary.
- [[dm-turn-jobs]] — DM jobs on the shared `jobs` queue: kinds, enqueue on commit/approval, priority claim per session, fencing, beats, reclaim idempotence, reconcile.
- [[dm-failure-and-gates]] — the failed-turn record in `jobs.result` with bounded model-output excerpts, and the closed rules-term lists (skills, conditions, damage types) with spells and modifiers/DCs not yet gated.
- [[actor-snapshot]] — the typed actor snapshot every DM prompt's state comes from (TASK-0140): build rules and the NPC-combatant join, aliases, the S0-to-S1 diff, the dm/seat/fiction views, token caps and the `state-overflow` failure.
- [[dm-talk-triggers]] — in-character talk draws a world reaction (TASK-0180, specs/065): rule 7 enqueue, code triggers, the coalesced `talk` turn, one `react` call, escalation and the chain cap.
- [[seed-npc-presence]] — seed NPC presence (TASK-0142, U8): the required per-beat `presence` map and its cross-checks, NPC aliases, the dm-visibility option on `scene-presence`, the seed-presence group in resolve, the Director's arrivals (spec 078), NPC lists read from logged presence, and the at-least-one human-seat rule.
- [[dm-narration-quality]] — narration quality (TASK-0106): the player-facing seed view, named public-only transcripts, facts v2, the blocking/advisory audit with the party-name filter, the in-fiction fallback.
- [[output-claim-gate]] — `checkClaims` (TASK-0143): the pure checker that refuses dead, downed or absent actors acting or speaking, wrong-actor deaths and drops, omitted deaths and wrong counts, and its audit, narrate and fallback callers.
- [[debug-view]] — the operator debug API (TASK-0116): four read-only `/dm` routes (events, jobs, seed, calls), cursors, the job-to-seq link, the `dm_model_calls` ledger as cost authority; and the debug page built on it (TASK-0117, `play/:sessionId/debug`).

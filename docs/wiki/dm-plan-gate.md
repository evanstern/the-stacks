# DM plan gate

Part of the DM runtime ([[dm-runtime]]). The failure record and rules-term lists are in [[dm-failure-and-gates]].

Since TASK-0110 a gate-refused action resolves before a Director stage change (encounter end, free mode), because resolve runs the action groups before the closing moves ([[dm-runtime]], "Resolve order"). The **plan gate** (`dm/gates/plan-gate.ts`, `checkPlan`, TASK-0112) is pure and runs first in resolve. It checks every actor and target id a step names against the S0 actors' `combatantId`s plus the combatants this turn's encounter start adds and, since spec 088 (TASK-0238), the Director's monster arrivals: `joining` holds `arrivingMonsters`, so an unseen monster named the beat it arrives passes. An encounter stays runnable until it has run (`encounterRan`: active, or an `encounter.started` ledger row whose order holds one of its monsters), even with some monsters already added. A refused action is narrated as not having happened: its fact line reads `refused (refused: <code>): it did not happen; nothing was rolled and nothing changed`, it carries no `followUps`, and the fallback skips its change sentences ([[dm-narration-quality]]). An action group with an unknown id resolves `refused` with `UNKNOWN_COMBATANT` before any step runs; the verdict reason is `not-a-combatant` (the id is an alias with no combatant; an exact NPC id never fails this way), `not-in-snapshot` or `absent` (TASK-0141: the S0 actor's `presence` is `absent`, unless the id is in the `arriving` input (seed arrivals and the Director's `arrivals`, spec 078); the code stays `UNKNOWN_COMBATANT`, operator ruling OQ-4). Since TASK-0194 (spec 068) the id check also accepts the exact id of an S0 `npc` actor with no combatant in a `check` `combatantId` or a `condition`/`heal` effect target, and the `ok` verdict lists such actors outside the order as `pull` ([[dm-runtime]]). Since spec 075 (TASK-0210) every non-presence field accepts that exact id, including `attackerId`, `targetId` and `onHit` damage. The operator ruled: "I actually think that the rule itself is incorrect -- we should be able to attack anyone regardless of combatant state." This reverses spec 068 OQ-4. A step that names an absent actor fails unless it is a `presence` effect with reason `arrived`. A `presence` effect may target any S0 actor, combatant or not. It never maps an alias. Since TASK-0161 (spec 058) `checkPlan` also checks model-written text against S0 with `checkClaims` ([[output-claim-gate]]): each step `reason`, a `check` step's `autoFail.reason`, and each condition effect `source` in `effects`, `onSuccess`, `onFailure` and `onHit` (`stepTexts`). The id check runs first and only a group that passes it has its text checked. `plannedDiff` is a presence-only diff: one change per `presence` effect target in any group and one per `arriving` seed NPC (`arrivingNpcs`, mirroring the encounter-start branch of `seedPresence`, [[seed-npc-presence]]), so a reason that names an NPC the same turn marks `arrived` passes. A group whose action id is in `resumed` skips the text check (spec 057 reuses the paused plan). The first refused text is the group's `ReasonFailure` (`stepIndex`, `field`, `text`, `issues`) and the group resolves `refused` with `REASON_CONTRADICTS_STATE`; `resolveAction` takes the code from the verdict. A refused NPC group runs no step and the turn still advances. A passing text is never rewritten. The first-stage cut ([[dm-runtime]], TASK-0182) runs after the interpret and adjudicate schemas pass; `followUps` is a plain bounded string list (at most 6, 200 characters each), not a rules term. Since TASK-0208 (spec 079) the `move` step (`combatantId`, `leavesReachOf`) joins the id and text checks. Where `PlanInput.actors` maps the action id, an `attack` `attackerId` or `move` `combatantId` that is not the action's actor (party scope: not a party combatant) resolves the group `refused` with `STEP_ACTOR_MISMATCH`; monsters are exempt. Since TASK-0244 (spec 087) a turn-mode party group whose only step actor (`stepActors`) is an off-turn conscious AI companion gets the held verdict `TURN_HELD` (`heldFor`; a plan-gate literal, not a `RefusalCode`, no event), and a group that also names another actor is refused `STEP_ACTOR_MISMATCH` with reason `off-turn`; a human PC named off turn still acts. Verdicts are stored as `checkpoint.planGate` (absent on older rows). The declare gate refuses a declaration for a downed character with `CHARACTER_UNABLE` ([[proposal-gate]]). The audit's option-menu check exempts the clarify question (specs/073), so a clarify turn that ends in its question passes.
**`askUndeclared`** (`gates/plan-gate.ts`, spec 077) is pure and runs in the runner after the cut and before `clarifyHolds`. Two rules turn a reading into a clarify with a fixed question. The other-player question (and the `help` step's `helperId`, spec 084) names the other PC's player and the declarer, and ends "What does <declarer> do instead?", never on the stock "What do you do?" (TASK-0204). A Stealth, Deception or Intimidation check runs only when the declaration's wording names that manner (`MANNER_SKILLS` cues). A check or attack from a character-scope action may not roll for another human's PC. Party-scope actions, saves, effect targets and AI companions skip the manner rule. Each ask is counted as `asked` on `dm.plan.cut`.
**Help and opposition** (spec 084, TASK-0128). A `help` step is a foreign actor if its `helperId` is not the action's own (`STEP_ACTOR_MISMATCH`), and `askUndeclared` reads `helperId` for the other-player question. The gate reads a `help` step's `helperId`, `allyId` or `targetId`, and an opposed check's `opposedBy`, as ids that must exist. An opposed check whose opponent lacks the stat for its rule, or an ability-check `help` whose helper has no `stats`, is refused `STAT_UNDEFINED`; a joining combatant is skipped. `NOT_PROFICIENT` is raised only by the engine at resolve ([[dnd5e-engine]]).
**Spell rule** (spec 083, `spellGap`). A `spell` step is strict (SRD id, slot level, no numbers). The gate refuses `SPELL_UNKNOWN` (no SRD record), `SPELL_NOT_PREPARED` (not on the caster's seed list), `SPELL_UNRESOLVED` (not in the engine table, or wrong slot level), `STAT_UNDEFINED` (no spellcasting modifier or target save), and an intent `spell` reading with no spell step. Another member's spell is `STEP_ACTOR_MISMATCH`.

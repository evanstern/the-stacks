# DM narration quality

Part of the DM runtime ([[dm-runtime]]); failure records are in [[dm-failure-and-gates]].
Spec: `specs/034-narration-quality/` (contracts `player-facing-context.md`,
`narration-facts.md`; `fallback-summary.md` and `audit-criteria.md` are history, retired by spec 103).

## Player-facing seed view

`seed/views.ts` exports `PlayerSeedView` and `playerFacingSeed(seed)`. The view copies only
player-facing fields: title, goal statement, location (name, features, mood, senses), opening
framing, `openingPremise` (`opening.premise`, required), NPC name/role/voice/want/detail/appearance, and character identity, portrayal, `knows`
and relationship kinds. It also copies `location.ways`, minus ways gated by `after` on a zone not yet revealed (`visibleWays`, TASK-0334). `openingScene(view)` builds the `scene.changed` payload (title, summary, location, `description` from the features capped at 1000 characters, `ways`, and a `cast` of id, name, role and appearance) from the view only (spec 091). `dmOnlySeedText(seed)` lists every DM-only string, for tests; it is built over `dmOnlySeedPaths(seed)`, the JSON Pointers of the same fields, which the operator seed route returns as `dmOnlyPaths` ([[debug-view]]). The
narrate builder (`prompts/narrate.ts`) and `companion.ts` take the view (the chronicle prompt takes the roster only);
DM-only seed facts never reach a player-facing prompt. The director still sees the full seed.

## Transcript and facts

`transcriptEntries(tail, roster?)` in `prompts/common.ts`: with a roster (`rosterOf(party)`) it
drops non-public rows and names speakers; without one it is the DM-side form (director
and interpret): every entry is kept, and a human is labelled by the seated character id, never a
user id (TASK-0302, spec 096: `seatsOf(party)` maps a player's user id to the character they seat,
`dmActorLabel` returns the character id, an `ai:`/`system` actor, or `a player`; `beatEntries`
labels a party-scope item the same way; the optional third argument `seats` carries the map). `NarrationFacts` (`facts.ts`, `buildNarrationFacts`) carries trigger, actions
with rolls and changes, `npcTurn`, director pacing, `modeChange`, present NPCs,
`clarify` questions, plus v2 fields: `party` (id, name, controller), `events` (public encounter
and turn changes, plus a `presence` fact from each `scene-presence.changed` row: name, new presence and reason; the name falls back to the seed NPC name) and `setting` (`locationName`, `openingFraming`). At scene start `openingSection` (`prompts/narrate.ts`) adds place, premise, goal, framing, each party character (name, class, look) and each NPC present at the first beat (`beats[0]` declaration minus S1 absent, not the Director's beat); it names characters, never players or controllers. `party` stays for the roster. The `npcNames` field is gone (TASK-0140): the world list
now comes from the snapshot. A roll fact carries its `target`, and since spec 070 its `band`, `margin` and `consequence` (declared stakes text, by batch, every band since spec 080) and, on a success band, `revealed` (the clue text) when the check row has a band; a free retry reads `no roll needed: success`. `settled` holds the death saves rolled for combatants the turn passed (`FactSettled`; a `death-saves` change), and a turn with only settled facts is narrated. The talk path builds facts with `trigger: "talk"` and no actions, so the checks refuse digits and dice language ([[dm-talk-triggers]]). The talk path builds facts with `trigger: "talk"` and no actions ([[dm-talk-triggers]]). An `intent` turn (spec 066 FR-031) fills `NarrationFacts.direct`: narrate passes `directBatches` (`{ name, batchId }` of each public direct `intent.recorded` carrier in the window with a `batchId`) and `buildNarrationFacts` collects the batch's ledger rows as one `FactSettled` per batch; `nothingToNarrate` is false while `direct` is non-empty. `factEntries` renders
the facts for the prompt; `renderDiceLines` (now `renderRows(...).map(text)`, `fact-sheet.ts`) still renders every number, including a joiner's initiative roll from `facts.pulled` (TASK-0213; the narrate prompt lists it as `Joined the fight`). The narrate prompt renders a presence fact as `Event: <name> is now <presence> (<reason>)`.

## State sections from the snapshot

`characterSections(snapshot)` (`prompts/narrate.ts`), used by the narrate prompt,
renders S1 ([[actor-snapshot]]) once in the `fiction` view under `CAPS.snapshotFiction` (800) and
splits it into three sections: `## Scene state` (the stage lines), `## Party (player characters)`
(party actors) and `## Other characters (the world)` (every other actor, so a goblin dead since an
earlier turn appears as dead). The `fiction` view prints no digit and no id: it prints name, kind,
controller ("human player" or "AI companion"), life state, conditions and presence. An overflow
throws `SnapshotOverflowError` and fails the turn with `state-overflow` ([[dm-runtime]]).

## Check node (TASK-0272, spec 103)

`nodes/check.ts` replaces the audit loop. It is pure: no model call, no regenerate loop, no fallback summary. One `dm.narrate` call fills the slots; `checkNarration` (`narration-check.ts`, `CheckInput`, `CheckIssue`) then tests the `describe` and `ask` slots sentence by sentence. `restate` is code-validated by `parseSlots`.

Spec 108 (TASK-0298) streams the slots. `narration-stream.ts` (`createNarrationStream`, pure) takes the check input minus the slots (`checkBase` in `nodes/check.ts`, shared with the check node) and the fact sheet. `push(delta)` strips a leading think block, finds slot tags with the exported `TAG`, and emits a `describe` sentence only when it is complete and passes the same rules the check applies: `dropDigitSentences` (the `parseSlots` digit drop), then `checkNarration` with no `leak` or `digit` issue. It holds an unclosed quote, a stock ending and anything past the prose cap. `restate` emits once after the `parseSlots` rule; `ask` waits for `finish(kept)`, which sends the rest of the kept describe only when what was sent is a prefix of it, so the settled row replaces the block when the two disagree. A property test pins the prefix invariant. The check record gains `firstTokenMs`, `firstProseMs` and `firstProseAt`, and `check` logs `dm.narrate.first-token`. `sentencesOf` is exported from `narration-check.ts`.

- **Leak** (hidden information): a unique alias of an actor whose S1 presence is `absent` (kind `absent-actor`, or `unmet-success` when `FactRoll.unmetSuccess` names the actor), a whole-word unrevealed zone name (`fogged-zone`), or a whole `dmOnlySeedText` entry (`dm-only-text`). Quotes, negation, "no sign of" and a question do not count. `CheckInput.departedIds` lists actors whose presence changed to `absent` in this beat's own `scene-presence.changed` rows (the check node reads `resolve.appendedRows`); S1 already shows them absent, so the absent-actor leak skips them (a fled actor may be narrated fleeing).
- **Contradiction**: a digit (`digit`), dice language with no roll (`dice-language`), or a death or down word whose subject, the unique alias just before it, is not in that life state (`life-state`, subject by proximity).

Spec 112 adds the speech rule. `speechLeaks(snapshot, text, speakerId)` tests each quote interior (or, with an explicit `CheckInput.speakerId` and no quote mark, the whole text): speech may name an actor only when the party has met them (`met`) or the speaker knows them (`knows`), and may never name a fogged zone. A hit is kind `unmet-actor` (or `fogged-zone`) with an `inner` sentence. The absent-actor and fogged-zone narration rules skip whole-speech text. `dropPlan(issues)` splits hits into whole sentences to drop and inner sentences to cut from inside a quote; `dropSentences(text, sentences, inners)` cuts the inner sentence and drops the whole sentence when a quote is left empty. The check node and the talk path both use them. The playtest auditor mirrors the rule ([[playtest-harness]]).

A leak or digit sentence is dropped (`dropSentences`) and a `dm`-visibility correction `Correction (hidden): dropped "<matched>" - <detail>` follows. A `life-state` or `dice-language` hit ships and a public `Correction: <detail>` follows. `submitNarration` (resolve) submits each correction as an AI-DM `talk` proposal. Nothing blocks play: a narrate call error ships restate, rows and the State line with `narrateError` in the record. `CheckRecord` (`leak`, `contradiction`, `corrected`, `shippedProseSha256`) is the checkpoint's `narration.check`; pre-0272 rows keep a `LegacyAuditRecord` (`attempts`, `final`) that readers still accept. Off-turn acts, omissions and counts are no longer checked; the fact rows are the defence (constitution VII). `namedActorIds` now lives in `snapshot/aliases.ts`; `narration-words.ts` keeps only the dice, death and unconscious words, `EITHER_OR_END`, `STOCK_ENDING` and `hasCountClaim`.

`dm.audit`, `dm.audit-v17`, `claims.ts` (`checkClaims`), `fallback.ts` (`factualSummary`) and `nodes/audit.ts` (`deterministicChecks`) are deleted. The `dm.audit` purpose is gone. Output claim gate: [[output-claim-gate]] (retired).

## Withheld inputs

`withholdRefusedInputs` (`nodes/narrate.ts`) runs before the model call. It withholds a ruling, follow-up, monster line or `goalNote` when `checkNarration` reports a `life-state` or `dm-only-text` hit on it, and a `goalNote` that states a count (`hasCountClaim`) or was written before a failed check. The check node records each withheld text as a `CheckIssue` with a `withheld ...` detail.

## Fact sheet (TASK-0245, spec 098)

`buildFactSheet` (`dm/fact-sheet.ts`, pure, in narrate's import closure) wraps `NarrationFacts` (its `settled` record) with `restate` targets (resolution `applied`, `partial`, `no-effect`, `refused`, `clarify`, `held`), code `rows` (`renderRows`: roll and change rows plus `refusal` rows from `REFUSAL_REASON`), `speakers`, the allowed `slots` (`describe` and `ask` on scene start; `restate` and `describe` on every other routine turn, with no `ask` slot; a clarify turn also has none, the code `ask` ships), a code `ask` (the first clarify question, verbatim) and a `state` line. `renderStateLine`: status clauses then a floor clause; it holds no `?`; a talk reply has none (`state` null; an escalate that starts a fight appends `State: The fight begins. It is <name>'s turn.` in `talk-turn.ts`). The model writes `[restate]`, `[describe]`, `[ask]` slots; `parseSlots` strips every label form at line start (`[x]`, `[x]:`, `x:`, `**x:**`, any case; a label word mid-sentence is no tag), drops disallowed slots, replaces a digit or empty restate with the code default (`<subject> means to: "<text>".`), keeps a model ask only as one open question, forces `sheet.ask` when set, and an untagged reply is `describe`. `composeReply` ships restate, describe, ask, then rows and the State line; the rows still ride the narration text (TASK-0247 moves them to the ledger). `NarrateOutput` gains `sheet` and `slots`; an empty restate falls back to `defaultRestate`. The transcript renders the text with `whitespace-pre-line`. Spec 103 adds `why` rows (`renderWhyRows`: one row per `PlanFact` from the beat's `intent.recorded` rows; `dc` renders `DC <dc> (<rule>)`; `unserved` renders none) after the change rows and before the State line, and `parseSlots` drops any describe or ask sentence that holds a digit. Spec 104 (TASK-0269) widens the source of those `why` rows: narrate renders one for every public `intent.recorded` row in the window `(W0, W1]`, not only the rows resolve appended this job, so an Intent settled before the job (a human DM's approval, a ruling turn) is narrated once. `W1` is `projections.throughSeq` (stored as `NarrateOutput.factsThrough`); `W0` is the newest prior checkpoint's `factsThrough`, else the newest earlier `narration` row's seq, else 0 (`NodeDeps.loadEvents`, [[dm-runtime]]). Spec 111 (TASK-0337) adds the deed row: `FactSettled.deed` (`{text, stopped}`) is set on every `direct` entry (`BuildFactsInput.directBatches` gains `text` and `stopped`, and `batchId` may be null, so a stopped Intent with no engine rows still yields an entry), `renderRows` emits one `deed` row (`deedLine`: `Deed: <name>: <Intent text>`, plus ` (stopped, <code>)`) before that entry's roll and change rows, and every trigger, not only `intent`, narrates the window's deeds (`dm/deeds.ts`, [[dm-runtime]]). The prompt's `factEntries` writes `Direct action: <name>: <deed text>` and a rule tells the model to describe every Direct action line in order. Narrate now always reads `loadPriorTurns` (the `priorActionIds` gate is gone). `buildNarrationFacts` finds an Intent's engine rows (`actionId: null`) through the action's batch ids: the resolve `result.batchIds`, else the resolved row's `batchIds` on a reclaim after `action.resolve` landed. A monster turn's Intent stages reach the plan lines as `reason: <text or kind>`.

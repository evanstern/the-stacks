container; its volume came up unmigrated. `apps/server/scripts/migrate.ts` and
`src/cli/create-operator.ts` both prefer `TEST_DATABASE_URL` over `DATABASE_URL` when
run on the host (by design, for the host-run integration-test path), and `.env`'s
`--env-file-if-exists` load lets that pre-existing `TEST_DATABASE_URL` win unless the
shell already set it — so a bare `pnpm db:migrate` / `auth:create-operator` silently
targets the long-lived TEST stack's database (port 25028) instead of this worktree's
APP database (port 15028). Fix: export both `TEST_DATABASE_URL=""` (falls back to
`DATABASE_URL`) and `DATABASE_URL=postgres://stacks:changeme@localhost:<DB_PORT>/stacks`
in the shell before running either script. Ran:
  TEST_DATABASE_URL="" DATABASE_URL=postgres://stacks:changeme@localhost:15028/stacks \
    pnpm --filter @the-stacks/server db:migrate
  TEST_DATABASE_URL="" DATABASE_URL=postgres://stacks:changeme@localhost:15028/stacks \
